一、网络基础

1. TCP三次握手

1.1 TCP是什么？

TCP（Transmission Control Protocol，传输控制协议）是一种面向连接、可靠的传输层协议。

主要特点：

  • 面向连接
  • 可靠传输
  • 字节流
  • 有序传输
  • 流量控制
  • 拥塞控制
  • 支持全双工通信

TCP主要通过：

  • 序列号（Sequence Number）
  • 确认号（Acknowledgment Number）
  • ACK
  • SYN
  • FIN
  • 重传机制

来保证数据可靠传输。

1.2 为什么需要三次握手？

TCP建立连接时需要确认双方：

  1. 客户端能够发送数据
  2. 服务端能够接收数据
  3. 服务端能够发送数据
  4. 客户端能够接收数据

因此需要三次通信完成双方状态确认。

1.3 三次握手过程

客户端 服务端

SYN, Seq=x

——————————>

                 SYN + ACK

                 Seq=y

                 Ack=x+1

<——————————

ACK

Ack=y+1

——————————>

      TCP连接建立

具体过程：

第一次握手

客户端 → 服务端：

SYN=1

Seq=x

表示：

客户端请求建立TCP连接，并告诉服务器自己的初始序列号是x。

第二次握手

服务端 → 客户端：

SYN=1

ACK=1

Seq=y

Ack=x+1

表示：

服务端收到客户端请求，同意建立连接，同时告诉客户端自己的初始序列号是y。

第三次握手

客户端 → 服务端：

ACK=1

Ack=y+1

表示：

客户端已经收到服务端的确认。

此时：

TCP连接建立

1.4 回答模板

TCP三次握手主要用于建立可靠的TCP连接。

第一次由客户端发送SYN，表示请求建立连接；

第二次服务器返回SYN+ACK，表示服务器收到请求并同意建立连接；

第三次客户端发送ACK，确认收到服务器响应。

三次握手完成后，双方进入ESTABLISHED状态，可以开始传输数据。

1.5 常见追问

为什么不是两次握手？

因为两次握手无法充分确认：

服务端的发送能力和客户端的接收能力。

第三次ACK可以让服务器确认：

客户端已经收到自己的SYN+ACK。

2. TCP四次挥手

2.1 为什么TCP断开连接需要四次？

TCP是全双工通信。

双方的数据发送方向需要分别关闭，因此通常需要：

客户端 FIN

服务器 ACK

服务器 FIN

客户端 ACK

共四次。

2.2 四次挥手过程

客户端 服务端

FIN

——————————>

                 ACK

<——————————

                 FIN

<——————————

ACK

——————————>

      TCP连接关闭

2.3 四次挥手详细过程

第一次

客户端：

FIN=1

表示：

客户端没有数据要发送了，希望关闭连接。

第二次

服务端：

ACK=1

表示：

服务端收到客户端关闭请求。

但是服务端可能还有数据没有发送完。

第三次

服务端数据发送完成后：

FIN=1

表示：

服务端也没有数据需要发送了。

第四次

客户端：

ACK=1

表示：

客户端收到服务器的FIN。

连接关闭。

2.4 TIME_WAIT是什么？

主动关闭连接的一方通常会进入：

TIME_WAIT

主要作用：

  1. 确保最后一个ACK能够到达对方
  2. 防止旧连接的数据包影响新连接

经典等待时间：

2MSL

3. UDP

3.1 UDP是什么？

UDP（User Datagram Protocol）是无连接的传输层协议。

特点：

  • 无连接
  • 不保证可靠传输
  • 不保证顺序
  • 不负责重传
  • 协议头简单
  • 传输效率高
  • 延迟较低

3.2 TCP与UDP对比

项目 TCP UDP
连接 面向连接 无连接
可靠性 可靠 不保证
顺序 保证 不保证
重传 支持 不支持
流量控制 支持 不支持
拥塞控制 支持 不支持
速度 相对较慢 相对较快
应用 HTTP/HTTPS、SSH DNS、DHCP、流媒体等

3.3 常见UDP应用

DNS（Domain Name System 域名系统的缩写）

通常：

UDP 53

DHCP（Dynamic Host Configuration Protocol 动态主机配置协议）

使用：

UDP 67/68

SNMP（Simple Network Management Protocol 简单网络管理协议）

通常：

UDP 161

SNMP Trap

通常：它允许被管理的设备在出现特定事件时主动向网络管理系统（NMS）发送消息。这种机制使得网络管理员无需不断轮询设备，从而节省了计算资源。

4. ARP

4.1 ARP是什么？

ARP（Address Resolution Protocol 地址解析协议）用于：

根据IPv4地址查询对应的MAC地址。

例如：

IP：

192.168.1.100

MAC：

AA:BB:CC:DD:EE:FF

主机需要发送数据时，如果知道目标IP但不知道MAC，就会使用ARP。

4.2 ARP工作过程

例如：

客户端：

192.168.1.10

目标：

192.168.1.20

客户端广播：

Who has 192.168.1.20?

目标主机回复：

192.168.1.20 is at AA:BB:CC:DD:EE:FF

客户端将结果保存到：

ARP缓存表

4.3 常用命令

Windows：

arp -a (用于显示本机ARP缓存表，即当前已解析的 IP地址与MAC地址映射关系。)

Linux：

ip neigh

(ip neigh 命令是用于管理 IP 邻居表的工具，它允许用户添加、删除或显示 ARP（IPv4）或 NDP（IPv6）的静态记录。这些记录是协议地址和链路层地址之间的绑定，用于在同一链路上共享的主机。)

8. ICMP

8.1 ICMP是什么？

ICMP（Internet Control Message Protocol 网际控制报文协议）主要用于：

网络状态检测和错误报告。

常见工具：

ping (ping 是一个用于测试网络连接和诊断网络问题的工具。它的全称是 Packet Internet Groper，主要用于检测两个设备之间的连通性和网络延迟。)

traceroute (traceroute 是一种网络诊断工具，用于追踪数据包从源主机到目标主机的路由路径。)

tracert (Tracert（Trace Route）是一个在Windows操作系统中用于诊断网络连接问题的命令行工具。 它可以帮助用户确定数据包从源计算机到目标地址在网络中的路径。 Tracert 命令通过发送一系列 Internet 控制消息协议 (ICMP) 回显请求消息来工作，每个消息的生存时间 (TTL) 值逐渐增加，从而发现数据包经过的路由器的 IP 地址。)

8.2 Ping原理

Ping主要使用：

ICMP Echo Request

对方返回：

ICMP Echo Reply

(ICMP Echo Request报文主要用于检测网络连通性和诊断网络问题。 通过发送Echo Request报文并接收Echo Reply报文，可以判断目标主机是否可达以及网络延迟情况。)

例如：

主机A

|

| Echo Request

↓

主机B

|

| Echo Reply

↓

主机A

8.3 Ping不通不一定代表服务器宕机

可能原因：

  • ICMP被防火墙禁止
  • 路由问题
  • 网络设备ACL
  • 服务器宕机
  • 网络链路故障
  • 安全设备丢弃ICMP

所以：

Ping不通 ≠ 服务器一定宕机。

二、路由与交换

9. VLAN

9.1 VLAN是什么？

VLAN（Virtual Local Area Network 虚拟局域网）：

虚拟局域网

作用：

在一个物理交换网络中划分多个逻辑广播域。

例如：

VLAN 10：办公网

VLAN 20：服务器网

VLAN 30：访客网

9.2 VLAN的主要作用

① 隔离广播域

减少广播流量。

② 网络隔离

例如：

员工网

×

访客网

③ 提高安全性

不同VLAN之间需要通过：

三层交换机 / 路由器 / 防火墙

进行通信。

10. Access端口

Access端口通常用于：

连接终端设备。

(Access端口是VLAN中最基础的端口类型，主要用于连接终端设备（如计算机、打印机和VoIP电话）。

每个Access端口只能属于一个VLAN，这意味着通过此端口连接的所有设备都被视为同一网络的一部分。Access端口不会对数据帧进行VLAN标记，因此传输的流量都是未标记的。)

例如：

PC

|

|

交换机

典型情况下：

PC → Access端口 → VLAN 10

PC通常不需要知道VLAN标签。

配置示例：

1
2
3
4
5

Switch(config)# interface FastEthernet0/1

Switch(config-if)# switchport mode access

Switch(config-if)# switchport access vlan 10

上述配置将FastEthernet0/1端口设置为Access端口，并将其分配到VLAN 10。此端口将仅允许来自VLAN 10的流量进入。

11. Trunk端口

Trunk端口用于：

在交换机之间传输多个VLAN。

(Trunk接口 是一种允许多个VLAN通过的交换机端口类型，通常用于连接交换机之间的端口。

Trunk接口可以接收和发送多个VLAN的报文，通过在数据帧中添加VLAN标签来区分不同的VLAN数据。)

例如：

交换机A

|

| Trunk

|

交换机B

可以同时传输：

VLAN 10

VLAN 20

VLAN 30

Trunk接口的配置

以下是配置Trunk接口的基本步骤：

  • 进入接口模式：
1

[Huawei]int e0/0/0
  • 定义二层端口为Trunk模式：
1

[Huawei-Etherneto/o/0]port link-type trunk
  • 配置Trunk端口允许通过的VLAN：
1

[Huawei-Etherneto/o/o]port trunk allow-pass vlan 10 20 30
  • 开启当前接口：(undo 禁止)
1

[Huawei-Etherneto/o/o]undo shutdown
  • 禁止Trunk传送某个VLAN的数据：
1

[Huawei-Etherneto/o/o]undo port trunk allow-pass vlan 10

11.1 Access与Trunk对比

项目 Access Trunk
主要连接 PC、打印机等终端 交换机、路由设备等
VLAN数量 通常一个 多个
VLAN Tag 通常不带标签 可携带802.1Q标签
（802.1Q是由IEEE定义的标准协议，主要用于实现虚拟局域网（VLAN）。

802.1Q协议通过在以太网帧中插入一个32位的VLAN标签来标识不同的VLAN。）

12. STP

12.1 STP是什么？

STP（Spanning Tree Protocol）：

生成树协议

主要解决：

二层网络环路问题。

12.2 为什么会有环路？

例如：

交换机A

/ \

/ \

B ——- C

如果没有STP：

广播帧可能在网络中不断循环。

导致：

  • 广播风暴
  • MAC地址表震荡
  • 网络性能下降
  • 网络瘫痪

12.3 STP解决方法

STP通过计算生成树：

逻辑上阻塞部分链路。

当主链路故障时：

重新计算生成树并恢复备用链路。

iptables 是 Linux 系统中用于管理防火墙规则的工具，基于内核的 Netfilter 框架实现。 它主要用于控制网络数据包的流入、流出和转发行为。 通过 iptables，用户可以定义规则来过滤、修改或转发数据包，从而实现网络安全和流量管理。

nftables 是一种用于管理 Linux 内核网络堆栈的工具，旨在替代传统的 iptables。它由 Netfilter 项目开发，提供了更高效、灵活且可读性更强的网络管理解决方案。

访问控制列表（ACL） 是由一条或多条规则组成的集合，用于描述报文匹配条件的判断语句。这些条件可以是报文的源地址、目的地址、端口号等。ACL 本质上是一种报文过滤器，规则是过滤器的滤芯。设备基于这些规则进行报文匹配，可以过滤出特定的报文，并根据应用 ACL 的业务模块的处理策略来允许或阻止该报文通过。

安全组是一种云上的虚拟防火墙，用于控制云服务器或其他云资源的入站和出站流量，实现网络安全隔离和访问控制。
